NonconvexCore

NonconvexCore is the modelling and automatic differentiation core of the Nonconvex ecosystem. It defines the optimization model types, the objective and constraint functions, the differentiation machinery shared by all the Nonconvex solver packages, and the solver capability system.

This documentation is a fragment of the Nonconvex documentation and is also built standalone.

Models

Two model types are provided:

  • Model: variables are stacked in one (flattened) vector.
  • DictModel: variables are named (a Symbol or String per variable) and collected in an OrderedDict.

Both support arbitrary variable structures (scalars, arrays, dictionaries, structs, tuples, named tuples and nested combinations thereof), which are flattened to a vector transparently by the differentiation machinery. See Models.

Objectives and constraints

An objective function can be set with set_objective!, and inequality, equality and semidefinite constraints can be added with add_ineq_constraint!, add_eq_constraint! and add_sd_constraint!. Inequality constraints follow the convention f(x) <= 0 at feasibility.

JuMP models

JuMP models can be converted to DictModels with DictModel(::JuMP.Model) when JuMP is loaded. Models with nonlinear expressions are evaluated through one MathOptInterface Nonlinear evaluator, so the values, sparse Jacobian and Lagrangian Hessian of the whole model come from single evaluator passes. See JuMP models.

Derivatives

Derivatives are computed through the DifferentiationInterface backend system. The package-wide default backend is AutoZygote(), and it can be changed with set_ad_backend!. See AD backends.

Structurally sparse Jacobians and Hessians can be computed with sparse_jacobian and sparse_hessian, which detect the sparsity with SparseConnectivityTracer and color it with SparseMatrixColorings. See Sparse Jacobians and Hessians.

Function modifiers

Function modifiers customize how a specific function is differentiated, without affecting other functions in the model:

  • CustomGradFunction and CustomHessianFunction use user-supplied gradients, Jacobians and Hessians.
  • LazyJacobian supplies matrix-free Jacobian-vector and vector-Jacobian products.
  • TraceFunction records where a function is evaluated.
  • symbolify computes derivatives symbolically with Symbolics.

See Function modifiers and Symbolic differentiation.

Solver capabilities

ConstraintCapabilities describes the constraint types and bounds a solver supports, and checksubproblem! validates a model against a solver's capabilities before optimization. See Solver capabilities.

Package extensions

NonconvexCore uses package extensions for its optional integrations. To use a feature from an extension, load the optional dependency first (the extension then activates automatically):

  • NonconvexCoreJuMPExt: the JuMP model conversion — using JuMP first.
  • NonconvexCoreSymbolicsExt: symbolify — using Symbolics first.
